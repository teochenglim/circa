# v0.1.0 — Core: ingestion + storage

Status: **Shipped.**

## Planned scope

- Scrape client in `internal/ingest/scrape` (see [DESIGN/04](../DESIGN/04_design_collection_and_ingestion.md) §4.2): configured target list (URL, interval, optional labels), `prometheus/common/expfmt` text parsing. No collector code, no `node_exporter/collector` dependency — pointing at a new source is a config change, not a code change.
- Tier-0 round-robin ring buffer (see [DESIGN/03](../DESIGN/03_design_storage.md)), in memory + disk persistence, no compression yet.
- `/api/v1/query_range` reading from the tier-0 buffer.
- No UI yet, no `/metrics` exposition yet — this milestone is the minimum pipeline: scrape in, store, query back out.

## Why this is first

Validates the single riskiest assumption in [DESIGN.md](../DESIGN.md) — that treating every metrics source as a scrape target is sufficient, with no local collection of Circa's own — and that the storage model can actually hold what gets scraped, before any UI/alerting/backup work depends on either.

## Built

Shipped as planned, with the source layout ARCHITECTURE.md's "Where things go" table calls for:

- `internal/config`: single-file YAML loading (`gopkg.in/yaml.v3`) for `server`, `ingest.scrape`, and `storage` — the fields this milestone needs. `features`/`alerting`/`backup`/`push`/`auth` are decoded into `Config` (so later milestones and `circa config check` have somewhere to land) but nothing acts on them yet. Missing/empty config file falls back to sane local defaults (`:9100`, `./data`, 2h raw retention, no scrape targets).
- `internal/ingest`: the normalize/fan-out seam from ARCHITECTURE.md's layering diagram — a flat `Sample` shape and a `Pipeline` that fans one ingested sample out to every registered `Consumer`. Only one source (scrape) and one consumer (storage) exist yet; this seam is what lets influx/remotewrite sources and alert/anomaly/backup consumers bolt on later without reshaping it.
- `internal/ingest/scrape`: one goroutine + ticker per configured target, `prometheus/common/expfmt` text parsing. Counters/gauges/untyped map straight to a sample; histograms and summaries are flattened into their component series (`_bucket`/`_sum`/`_count`, per-quantile) the same way Prometheus itself represents them internally, rather than being silently dropped.
- `internal/storage`: tier-0 ring buffer, one fixed-size file pair (`<hash>.tier0` binary ring buffer + `<hash>.meta.json` sidecar) per series, keyed by a sha256 of the canonical name+label string. Capacity = `retention.raw / interval`, wraps in place — no unbounded growth. Plain `os.File` `WriteAt`/`ReadAt`, no mmap and no compression (both are v0.2.0's job); this was simple enough to get right and fast enough at scrape-interval write rates that reaching for mmap now would have been premature.
- `internal/query`: the only reader of `internal/storage`, per the architecture's "query never touches storage directly" rule. Adds `__name__` into the returned label set so results already look like Prometheus's own matrix shape.
- `internal/httpapi`: `GET /api/v1/query_range` (exact-label-match only — no PromQL yet) plus `/healthz`/`/readyz`, added now rather than deferred because `k8s/20-daemonset.yaml`'s existing probes already point at `/healthz` and would otherwise crash-loop on a real deploy.
- `cmd/circa`: wires config → storage → ingest pipeline → scraper → query engine → HTTP server, with graceful shutdown on SIGINT/SIGTERM.

**Deferred to later milestones, as planned:** UI, Gorilla compression, tier-1/tier-2 downsampling, `/metrics` exposition, config CLI (`config init`/`check`), auth, push/pull remote-write, alerting, anomaly detection, backup/federation.

**Bugs found and fixed during implementation:**

- `prometheus/common@v0.70.0` changed `expfmt.TextParser{}` (zero-value) to panic with `"Invalid name validation scheme requested: unset"` — the package now requires `expfmt.NewTextParser(model.LegacyValidation)`. Caught by `TestFetchDecodesAllMetricTypes`, fixed in `internal/ingest/scrape/scrape.go`.

**Verified beyond unit tests:** `go vet`/`go test ./... -race -cover` all green; built the actual `circa` binary and ran it end-to-end against a throwaway Prometheus-format exporter — confirmed scraping, disk-persisted tier-0 files, and `/api/v1/query_range` all round-trip real data, not just fixtures. `semgrep` (p/golang, p/sql-injection, p/secrets, p/owasp-top-ten) and `trivy` (filesystem + built image) both report zero findings.
