# v0.2.0 — Visibility: UI + compression

Status: **Shipped.**

## Planned scope

- Static dashboard (plain HTML/CSS/JS) embedded via `go:embed`, served from `/` (see [DESIGN/05](../DESIGN/05_design_ui.md)).
- uPlot charts wired to `/api/v1/query_range`.
- Multi-tier downsampling: min/avg/max rollups from tier-0 into tier-1/tier-2.
- Swap raw per-slot storage for Gorilla-style delta-of-delta timestamp + XOR value encoding (see [DESIGN/03](../DESIGN/03_design_storage.md) §3.2). Prototype against `dgryski/go-tsz` (or the `tsenart/go-tsz` fork) before committing to a from-scratch bit-packer.
- Re-measure disk footprint against the v0.1.0 raw-storage baseline and record the actual compression ratio achieved (§3.3 cites ~10x as a target, not a guarantee).

## Why this is next

Once ingestion+storage are in, the highest-value next step is making the data visible and keeping it cheap to hold — before layering config, auth, or any feature-flagged subsystem on top.

## Built

Shipped, with one deliberate deviation from the plan (from-scratch bit-packer, not `go-tsz`) and one simplification (min/avg/max stored as three ordinary series, not a shared-timestamp triplet format):

- **Compression** (`internal/storage/gorilla.go`, `bitstream.go`): a self-contained Gorilla-style encoder — delta-of-delta timestamp buckets + XOR value encoding with leading/trailing-zero window reuse, operating on second-granularity timestamps (sub-second precision isn't meaningful for this domain). Wrote this from scratch rather than wrapping `dgryski/go-tsz`: that library streams into one ever-growing block, which doesn't fit the ring-buffer-of-chunks model below, and reusing it would have meant as much integration work as writing the well-documented algorithm directly. Round-trips correctly across regular/irregular intervals, negative/zero/huge values, and truncated/corrupt input (now returns an error instead of silently decoding garbage — caught by a dedicated test).
- **Storage engine rewrite** (`internal/storage/storage.go`): replaced v0.1.0's fixed-16-byte-per-point ring with a fixed ring of `chunksPerSeries` (8) Gorilla-compressed chunk files per series, each holding a bounded run of points sized off retention/interval. A chunk is re-encoded and rewritten whole on every append — simple and correct at scrape-interval rates, not the most efficient I/O pattern possible. Each chunk file's size on disk reflects its actual compressed content (no worst-case padding), so total directory size is a true compression measurement, not an allocation.
- **Compression ratio, actually measured** (`compression_test.go`): a realistic mix of constant/counter/random-walk metrics compresses **3.14x** over the v0.1.0 raw-storage baseline (16 bytes/point) — below DESIGN/03 §3.3's ~10x aspiration at this scale because per-series JSON metadata overhead doesn't amortize much yet; a synthetic constant-value series in isolation hits **55.2x**. Ratio should improve with more points per chunk (larger `retention/interval`) and degrade for highly volatile metrics — both expected per the algorithm's own tradeoffs, not a bug.
- **Multi-tier downsampling** (`internal/storage/tiered.go`): `TieredStore` wraps raw/minute/hour `Store`s; every ingested sample is folded into an in-memory min/avg/max accumulator per series per tier, flushed as three sub-series (`<metric>#min`/`#avg`/`#max`) when the bucket rolls over. Reusing the tier-0 engine 3x per rollup (instead of a shared-timestamp 3-value chunk format) traded some timestamp-stream overhead for a single well-tested storage engine — a deliberate simplification worth revisiting if disk footprint at scale demands it. A bucket still open when the process stops is lost on restart (no accumulator persistence) — acceptable for now, noted for later.
- **`internal/query`/`internal/httpapi`**: `QueryRange` now takes a `tier` (`storage.TierRaw`/`TierMinute`/`TierHour`), returning single-valued `Result`s for raw or `AggResult`s (min/avg/max) for rollups. `GET /api/v1/query_range` gained a `tier=raw|minute|hour` param and, for non-raw tiers, `min`/`max` arrays alongside `values` (which holds the bucket average) — additive, so existing raw-tier clients are unaffected. New `GET /api/v1/series` lists every currently-known series (name + labels), letting the UI populate a metric picker without hardcoding anything.
- **UI** (`web/`): static dashboard — `template/index.html` + `static/{css,js}/app.*`, embedded via `go:embed` (`web/embed.go`), served at `/` and `/static/*`. Vendored uPlot v1.6.32 (51KB, matching DESIGN/05's estimate) rather than an npm build step. The page fetches `/api/v1/series` to populate a metric picker, then `/api/v1/query_range` on metric/range change (auto-selecting tier from the chosen range: raw ≤1h, minute ≤7d, hour beyond) and renders via uPlot, auto-refreshing every 15s. Verified against real rendered output (Playwright screenshot), not just `curl`/unit tests — see below.

**Verified beyond unit tests:** full suite green (`go vet`/`go test -race -cover`, all packages including new `internal/storage` chunk/tier logic and `web`); `docker build` + container run confirmed the dashboard and static assets serve correctly from the embedded binary; ran the actual `circa` binary against a **real `node_exporter` v1.12.0** (not just synthetic fixtures) — ingested 513 real series including flattened histograms/summaries from v0.1.0's scrape client, confirmed via `/api/v1/series` and `/api/v1/query_range`; took an actual browser screenshot (via the `playwright` CLI) of the dashboard rendering a live `go_goroutines` chart with correct data and legend, confirming the JS actually executes correctly (per this repo's own rule that `curl`-only checks don't cover client-side JS). `semgrep` and `trivy` (filesystem + built image) both report zero findings.

**Bugs found and fixed along the way:**

- **(Pre-existing, not introduced this milestone.)** `config.example.yaml`'s `retention.minute: 7d` / `retention.hour: 365d` were never actually parseable — Go's `time.ParseDuration` has no `d`/`y` unit, and this went unnoticed in v0.1.0 because nothing read `retention.minute`/`.hour` yet. `internal/config`'s `Duration.UnmarshalYAML` now special-cases a trailing `d`/`y` unit before falling back to `time.ParseDuration`, so `7d`/`365d`/`1y` all parse as intended (see `TestDurationParsesDayAndYearUnits`).
- **Missing series directory crashed queries instead of returning empty.** Found via manual testing: if a series' on-disk chunk directory disappears while the process is running (in practice this happened when a leftover test instance and a cleanup command collided — see below — but it's a real robustness gap regardless of cause), `Store.QueryRange` returned a hard error instead of treating it as "no data," and the next `Append` never recreated the directory, permanently breaking that series until restart. `readAll()` now treats a missing directory as empty, and `writeChunkFile()` self-heals by recreating it (`TestSeriesSurvivesExternalDirDeletion`).
- **Stale chart left on screen when switching metrics, especially on query error.** The dashboard only cleared/redrew the chart on a *successful* response; switching to a metric whose query failed (e.g. hitting the bug above) left the previous metric's chart frozen on screen next to an easy-to-miss error line. `web/static/js/app.js` now clears the chart immediately when the metric/range selection changes (before the new query even resolves) and on any query error.
- **Not a code bug, but worth recording:** a "6 hour range shows data years in the future" report turned out to be a stale `circa` process from earlier manual testing (in this same debugging session) still bound to the dashboard's port, serving contaminated data accumulated across many ad hoc restarts/directory deletions — not the freshly built binary. Confirmed the actual minute-tier band-rendering code (min/avg/max together in one chart, exercised by any non-raw-tier query with exactly one matching series — untested in a browser until this session) renders correctly by re-running the real query response through uPlot in isolation. Take-away: kill background `make local-up` instances before trusting what's on screen.
