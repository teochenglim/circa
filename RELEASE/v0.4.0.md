# v0.4.0 — Intelligence: alerting + anomaly detection

Status: **Not started.**

## Planned scope

- Rule engine: metric selector + condition (threshold/rate-of-change/anomaly-bit) + hysteresis + severity (see [DESIGN/06](../DESIGN/06_design_alerting_and_anomaly_detection.md) §6.1).
- Webhook + Slack incoming-webhook notifiers behind a pluggable dispatch interface.
- Alerts view in the UI. Feature-flagged (`features.alerts`), default off.
- Per-metric k-means (k=2) ensemble, starting with 3–5 models per metric on staggered training windows (see [DESIGN/06](../DESIGN/06_design_alerting_and_anomaly_detection.md) §6.2).
- Anomaly bit embedded in the existing storage format (no separate time series).
- "What's unusual right now" ranked view in the UI. Feature-flagged (`features.ml`), default off — document rough CPU/RAM cost per 1,000 metrics before shipping.

## Why this is next

Alerting and anomaly detection both act on the storage/query foundation from v0.1.0–v0.3.0 and share the same "feature-flagged, default off" shape — grouping them keeps the rule-engine-to-anomaly-bit wiring (threshold conditions can reference the anomaly bit) as one milestone instead of a half-finished dependency across two.
