# v0.5.0 — Built-in system collection: node_exporter/Netdata-style, Linux + macOS

Status: **Shipped.**

## This reverses a documented design decision — read before starting

[DESIGN/04](../DESIGN/04_design_collection_and_ingestion.md) §4.1 and [ARCHITECTURE.md](../ARCHITECTURE.md) currently state, deliberately: *"Circa doesn't collect metrics — it ingests them"* — no `/proc`/`/sys` reader, no wrapped `node_exporter/collector`, a new source is a scrape target in `config.yaml`, not new Go code. That was itself a reversal of an *earlier* draft that did import `node_exporter/collector` directly (see §4.1's own history). This milestone reverses it back: local `/proc`/`/sys` collection returns as first-class, in-binary functionality, so a fresh install has real host metrics with zero external exporter required — directly motivated by v0.6.0's "zero-config, Netdata-like" UI goal, which needs data to show without asking the user to stand up node_exporter first.

**Before writing code**, update [DESIGN/04](../DESIGN/04_design_collection_and_ingestion.md) §4.1, [ARCHITECTURE.md](../ARCHITECTURE.md)'s "Circa doesn't collect metrics" convention note and its "Pointing Circa at a new metrics source" section, and [CLAUDE.md](../CLAUDE.md)'s explicit "don't add a `/proc`/`/sys`-reading collector" line — those docs govern how every past contribution (including agent-assisted ones) has approached this repo, and leaving them stale after this milestone would make the next change fight the same rule this one is deliberately breaking. Record *why* the second reversal is worth it (zero-config default vs. the earlier dependency/build-tag cost §4.1 already weighed) rather than silently deleting the old rationale.

## Reuse policy: reference both, import/vendor neither

`internal/collect/` is a from-scratch Go implementation in both directions — never `import "github.com/prometheus/node_exporter/collector"`, and never copy/vendor files out of the local `node_exporter/` or `netdata/` clones into this repo.

- **netdata** (`netdata/`) is GPL-3.0 (confirmed: `netdata/LICENSE`) — copying its C source into Circa's Apache-2.0 tree isn't a style choice, it's a real licensing conflict. Reference it for coverage ideas and edge cases only, same posture already established for v0.4.0's anomaly detection (`DESIGN/10_ml_summary.md`: "matched against Netdata's real source," reimplemented from scratch, never ported).
- **node_exporter** (`node_exporter/`) is Apache-2.0 — legally reusable, even vendorable, but deliberately treated the same as netdata here anyway: reference-only, own implementation. This is a quality/consistency choice, not a legal one — its `collector` package registers ~100 `kingpin.Flag()` package-level vars at import time and returns `prometheus.Metric` rather than Circa's `ingest.Sample`, so importing it wholesale would mean carrying that framework's side effects and a `client_golang`-round-trip adapter just to get a float64 out. Writing the parsing logic directly against `/proc`/`/sys` (and macOS's `sysctl`/`host_statistics`) keeps `internal/collect/` in Circa's own style and dependency-free, matching `internal/anomaly`'s "entirely from-scratch... avoids a heavy dependency" precedent (DESIGN/06 §6.2).
- Read `node_exporter/collector/*_linux.go` and `*_darwin.go` for exact field parsing (kernel `HZ` handling, `statfs` quirks, macOS `sysctl` MIB names) and `netdata/collectors/proc.plugin/` for which categories/edge cases to cover — but every line landing in `internal/collect/` gets typed and written fresh.

## Planned scope

- New `internal/collect/` package (naming TBD at implementation time) that reads `/proc`+`/sys` on Linux and the `sysctl`/`host_statistics`/`getifaddrs` syscalls on macOS, producing the same core metric set node_exporter's default collector set covers: `cpu`, `meminfo`, `diskstats`, `filesystem`, `netdev`/`netstat`, `loadavg`, `uname`.
- Normalizes collected values into the same `ingest.Sample` shape scrape/influx/remote-write already produce, and feeds `internal/ingest.Pipeline.Ingest()` the same way — nothing downstream (`internal/storage`, `internal/alert`, `internal/anomaly`, `internal/query`) should need to know a sample came from local collection rather than a scrape.
- Ticks on its own interval (config-driven, mirroring `internal/ingest/scrape`'s per-target ticker shape), not folded into the scrape loop — it isn't scraping anything, there's no target URL or HTTP round trip.
- **Platform scope: Linux and macOS (darwin) only for this milestone — no Windows.** Per-OS collectors behind build tags (`_linux.go`/`_darwin.go`, mirroring node_exporter's own file-naming convention, which is fine to mirror even though the code inside isn't). Windows has no `/proc`/`sysctl` equivalent at all — it's WMI-based (`windows_exporter`'s territory, a wholly separate mechanism, third codebase/license to evaluate separately) — **deferred to [v1.1.0](v1.1.0.md)**, after the v1.0.0 hardening/packaging pass, not part of this repo's roadmap through v1.0.0. Same for any other non-Linux/non-macOS target (*BSD, etc.).
- **Dev/test loop, since the primary dev machine is macOS**: write collectors the way node_exporter itself tests them — parse static fixture text (sample `/proc/stat`, `/proc/meminfo`, etc. content checked into `testdata/`) rather than requiring a live `/proc` to run `go test` — so Linux-path unit tests are meaningful from a Mac laptop. `.github/workflows/ci.yml` already runs on `ubuntu-latest`, so the Linux build and any integration-level test also gets exercised for real in CI on every push, independent of local dev OS; macOS collection is the one that can be exercised live locally.
- Config: a new `ingest.collect` (or `collect`) section — enabled state, tick interval, which collector groups are on. Decide at implementation time whether this defaults on (true zero-config, the point of this milestone) or stays opt-in like `influx`/`remotewrite` — leaning default-on given v0.6.0's zero-config goal, but confirm the CPU/RAM cost of always-on polling is negligible (it should be, node_exporter's own default footprint is small) before committing to that default.
- `circa config init`'s generated config and [config.example.yaml](../config.example.yaml) updated to reflect the new section either way.

## Why this is next

v0.6.0's Netdata-style dashboard is pointless on a fresh install with an empty scrape target list — this milestone exists to give it something to render without the user standing up node_exporter first, closing the "zero-config onboarding" open question flagged in [DESIGN/09](../DESIGN/09_design_tech_stack_and_roadmap.md) §9.3. It's sequenced *before* the UI work (not folded into it) so the UI milestone can build against a real, already-flowing local metric set instead of guessing its shape. It's sequenced *after* alerting/anomaly detection because those are more central to a host that's already being scraped from somewhere; this is specifically about hosts that currently show nothing at all.

Scraping an external node_exporter remains fully supported and unaffected — this is an additional always-available *source*, not a replacement for §4.2's scrape client, and existing deployments that already point at their own node_exporter/postgres_exporter/etc. see no behavior change.

## Built

Shipped as planned, with two additions beyond the original scope that turned out to be load-bearing once real deployment was considered: a Kubernetes container-vs-host `/proc` distinction, and Downward API identity labels.

- **`internal/collect/`** — package layout follows the "pure parse, thin platform I/O" split promised above: `collect.go` (shared `Collector`/ticker loop, `sample`/`charsToString` helpers), `linux_parse.go`/`darwin_parse.go` (build-tag-free parsing, fixture-testable from any OS), `linux.go`/`darwin.go` (the actual `/proc` reads, syscalls, and shelled-out commands), `unsupported.go` (`!linux && !darwin`, returns a clear "planned for v1.1.0" error rather than silently no-op'ing).
- **Metric set**: `node_cpu_seconds_total{cpu,mode}` (Linux, real counters from `/proc/stat`) vs. `node_cpu_usage_percent{mode}` (macOS, an instantaneous gauge from `top -l 1 -n 0` — deliberately a different metric name, since macOS has no no-cgo path to Mach's `host_statistics64` and this repo builds `CGO_ENABLED=0`); `node_memory_*_bytes` (curated subset of `/proc/meminfo` on Linux, `vm_stat` page counts × page size plus `hw.memsize` on macOS — different key vocabulary on each OS, since macOS has no single Linux-style "free" number); `node_disk_*_total` (per-device on Linux from `/proc/diskstats`, a single `device="total"` system-wide aggregate on macOS parsed from `top`'s `Disks:` line — real per-device I/O counters need IOKit, which needs cgo, out of scope here); `node_filesystem_*_bytes` (Linux: `/proc/mounts` + `unix.Statfs` per mount, filtered by a small virtual-fstype denylist; macOS: a single `unix.Getfsstat` syscall enumerates every mount directly, no denylist-then-loop needed); `node_network_*_total` (Linux: `/proc/net/dev`; macOS: `netstat -ib`, keeping only each interface's link-layer row — see `parseNetstatIB`'s doc comment for why naive whitespace-splitting doesn't work here, the Address/MAC column is sometimes entirely absent, shifting every later field); `node_network_primary_info{device}` (both platforms — the interface actually carrying the default route, read from `/proc/net/route`/`route -n get default`, not guessed by name, since "the Wi-Fi interface" has no fixed name across machines); `node_load1`/`5`/`15`; `node_uname_info{sysname,release,version,machine,nodename}`.
- **Reuse policy held**: no import of `node_exporter/collector`, no vendored files from either local clone — every parser is fresh, checked against real captured output (a local Linux container via Colima/Docker for the Linux side, this repo's own dev machine for the macOS side — see "Verified" below), not just recalled field layouts.
- **Config** (`internal/config/config.go`): `Features.Collect` is a `*bool` (not a plain `bool` like every other flag) so "absent from the file" and "explicitly `false`" are distinguishable — `CollectEnabled()` returns true unless the file explicitly disabled it. This is the one feature flag that defaults **on**. New `Ingest.Collect.Interval` (default 15s). `circa config init`'s generated template, `config.example.yaml`, and both `k8s/`/`helm/circa` manifests all default `features.collect: true` and `ingest.scrape.targets` to **empty** — scraping a co-located node_exporter is no longer the zero-config path, self-collection is.
- **Kubernetes identity and `/proc` scoping** (not in the original planned scope — surfaced once actually deploying this as a DaemonSet): a pod's own `/proc` is its container's, not the node's, so `internal/collect/linux.go` reads a `$HOST_PROC`-overridable root (default `/proc`) instead of a hardcoded path; `k8s/20-daemonset.yaml` and `helm/circa`'s chart bind-mount the host's real `/proc` read-only at `/host/proc` and set `HOST_PROC` accordingly (the same pattern node_exporter's own manifests use). `filesystemSamplesLinux` deliberately does **not** honor `HOST_PROC` — see its doc comment for why a bind-mounted host `/proc/mounts`'s *paths* aren't safely `statfs`-able from inside the container's own mount namespace without a much bigger host-root-bind-mount lift (node_exporter's own `--path.rootfs` trick), which is out of scope here. Downward API env vars (`POD_NAME`/`POD_NAMESPACE`/`NODE_NAME`) are merged onto every self-collected sample via `Collector.labels` (a sample's own labels always win on collision), so a DaemonSet's per-node metrics stay distinguishable once federated (v0.7.0).
- **Dev/test loop delivered as planned**: fixture-based parser tests (`linux_test.go`/`darwin_test.go`) using real captured output, runnable from any OS; separate `linux_integration_test.go`/`darwin_integration_test.go` exercise the real `collectAll()` (real `/proc` reads, real syscalls, real shelled-out commands) — the Linux one only meaningfully runs in CI or a container, the macOS one runs live on every `go test` from the primary dev machine.

**Verified beyond unit tests**: every `/proc` field layout (`/proc/stat`, `/proc/meminfo`, `/proc/diskstats`, `/proc/net/dev`, `/proc/net/route`, `/proc/mounts`) and every macOS command's output (`top -l 1 -n 0`, `vm_stat`, `sysctl -n vm.loadavg`, `netstat -ib`, `route -n get default`) was captured from a real running system *before* writing the corresponding parser, not guessed from memory — the fixture tests use that captured output verbatim. Full suite green (`go vet`/`go test -race -cover`) on darwin natively, and cross-compiled + actually executed inside a real Linux container (Colima/Docker, `golang:1.26-bookworm`), including with `HOST_PROC` set to confirm the override path works. `TestCollectAllLinux` and `TestCollectAllDarwin` exercise the true end-to-end path (real `/proc`, real syscalls, real subprocess output), both green. `helm template`/`helm lint` and a hand-rendered `k8s/10-configmap.yaml` were both round-tripped through `circa config check` to confirm the generated YAML actually validates, not just renders.

**Deliberately deferred**: per-device disk I/O on macOS (needs IOKit/cgo); full host-filesystem visibility from inside a Kubernetes pod (needs a host-root bind mount with mount propagation, node_exporter's own `--path.rootfs` trick — bigger deployment lift than this milestone); Windows and every other non-Linux/non-macOS platform ([v1.1.0](v1.1.0.md)).
