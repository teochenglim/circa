# v1.0.2 — CVE patch: apache/thrift, golang.org/x/crypto, google.golang.org/grpc

Status: **Shipped.**

## What happened

A Trivy scan flagged three vulnerable dependencies (all transitive except `golang.org/x/crypto`, pulled in via `internal/auth`'s bcrypt use):

| Module | CVE | Severity | Installed | Fixed in |
| :--- | :--- | :--- | :--- | :--- |
| `github.com/apache/thrift` (indirect, via `github.com/apache/iceberg-go`) | CVE-2026-43871 | HIGH | v0.23.0 | 0.24.0 (denial of service via infinite loop) |
| `golang.org/x/crypto` | CVE-2026-56854 | — | v0.54.0 | 0.55.0 (`x/crypto/ssh`: auth bypass via unenforced source-address restrictions) |
| `google.golang.org/grpc` (indirect, via `github.com/prometheus/prometheus`) | CVE-2026-84304 | — | v1.82.1 | 1.83.1 |
| `google.golang.org/grpc` (indirect, same as above) | CVE-2026-84445 | — | v1.82.1 | 1.82.2 / 1.83.2 / 1.85.0-dev (xDS server DoS via crash on missing validation) |

## Fix

- `go get google.golang.org/grpc@v1.83.2 golang.org/x/crypto@v0.55.0 github.com/apache/thrift@v0.24.0` + `go mod tidy` — bumps all three to versions that clear every CVE above (grpc's two CVEs both need `1.83.2` to be fixed in one bump). No circa code changed; this is a dependency-only patch release, same shape as [v1.0.1](v1.0.1.md).
- Verified locally before pushing: `trivy fs --scanners vuln --severity CRITICAL,HIGH .` reports 0 vulnerabilities post-bump (previously 3 findings across these two lines). `go build ./...`, `go vet ./...`, and `go test ./... -race -cover` all pass (148 tests, 15 packages).
