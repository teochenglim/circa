## Built

- **Sizing calculator** (DESIGN/03 §3.3): `circa sizing` (`cmd/circa/sizing_cli.go`) estimates on-disk footprint from `-metrics` (series count), raw interval, and per-tier retention (defaulting to whatever `-config` points at, or `config.Default()`). Uses v0.2.0's *actually-measured* realistic-mix compression ratio (3.14x, `RELEASE/v0.2.0.md`) as the default assumption rather than DESIGN/03's ~10x aspiration — `-ratio` overrides it for a caller who's measured their own metric mix, or wants the 55.2x constant-value best case instead.
- **Packaging**: `packaging/systemd/circa.service` + `packaging/systemd/README.md` — a hardened (`NoNewPrivileges`, `ProtectSystem=strict`, dedicated `circa` user) unit for a bare-metal/VM host with no container runtime, the same per-node-agent shape as the Docker/Kubernetes paths. The Dockerfile, `k8s/`, and `helm/circa/` scaffolding already had real, buildable code behind them going into this milestone (verified again here) — nothing there was stale.
- **Docs pass — resource cost per feature flag** (DESIGN/08 §8.1.3): `config.example.yaml`, `internal/config/template.go` (the `circa config init` template), and README.md's new "What each feature flag actually costs" table all now state each flag's rough CPU/memory/network cost, qualitatively (no fabricated benchmark numbers) — `ml` is the one genuinely CPU-hungry flag, everything else is cheap or bursty-but-bounded.
- **DESIGN/09 §9.2 open questions**: every one resolved to what actually shipped rather than left as a live question — retention defaults, rules-file-vs-inline, per-node-only dashboard scope, backup cadence/mode/catalog-sharing, `apache/iceberg-go` vs. the community fork, basic-auth-is-sufficient, push-receiver auth (same basic auth as everything else), and zero-config onboarding (solved by `internal/collect`, not a default scrape target). See DESIGN/09 §9.2 for the full list with citations to where each was actually decided.
- **UI polish — self-metrics visualization** (the one substantive new-functionality item in this otherwise-refinement milestone): `GET /api/v1/selfmetrics` (`internal/httpapi/selfmetrics_api.go`) is a JSON snapshot of `prometheus.DefaultGatherer` — every package's RED self-metrics from v0.7.0, flattened (a histogram/summary becomes its `_sum`/`_count`). The dashboard's new Self-metrics page (`web/template/selfmetrics.html`, `web/static/js/selfmetrics.js`) polls it every 5s and builds a client-side rolling ~10-minute history to chart — there's deliberately no server-side time series for these values (self-metrics were never written to `internal/storage`), so every number on this page is real, live process state at the moment it was polled, never simulated (see this file's own earlier note about what *not* to build here).
- **UI polish — dark/light pass**: turned out to be nothing further to do. v0.6.0's design-token pass (`--bg`/`--surface`/`--fg`/`--cat-*` custom properties, `prefers-color-scheme: dark` override) already covers every page; the new Self-metrics page reuses the same `.overview-grid`/`.overview-card`/`.page-heading` classes and a new `--cat-self` token (the brand accent itself, not a new hue) rather than introducing its own styling, so it inherited correct light/dark rendering for free. No separate remediation pass was needed — recorded here so a future contributor doesn't go looking for one.
