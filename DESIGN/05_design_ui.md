# Circa — Design 05: Static HTML UI

- Build the frontend once (plain HTML/CSS/vanilla JS, or a small framework compiled to static assets) and embed it into the Go binary via `go:embed`, served from `/`. No Node.js runtime, no separate deploy artifact — this preserves the "single binary" property end to end.
- Charting library: **uPlot**. Benchmarks show it as by far the smallest and fastest canvas-based time-series charting library — at ~50 KB it's likely the smallest and fastest time series plotter that doesn't use WebGL/WASM, and when updating 3,600 points at 60fps it uses 10% CPU and 12.3MB RAM versus 40%/77MB for Chart.js and 70%/85MB for ECharts. For a single-binary tool aiming for a small footprint end-to-end, shipping a ~50KB dependency-free chart lib beats bundling Chart.js/ECharts/Plotly. One practical caveat from real-world use: uPlot's documentation is thin, mostly one markdown file plus reverse-engineering the TypeScript defs and demos, so budget extra time for chart wiring rather than assuming a quick integration.
- Dashboard sections to plan for: overview (system health at a glance — **built: v0.6.0**, the tabbed Overall/CPU/Memory/Network/Disk/Filesystem/Load/Metrics pages, **+Self-metrics page in v1.0.0**), per-source chart groups (grouped by scrape target / line-protocol measurement / remote-write origin, not by a fixed collector taxonomy — see [04](04_design_collection_and_ingestion.md); **built: v0.6.0**'s Metrics page), an alerts view, an anomaly/"what changed" view (see [06](06_design_alerting_and_anomaly_detection.md); **built: v0.4.0**), a **status/config page** (see [08](08_design_config_auth_ops.md); **built**, `GET /status`), and a lightweight **self-metrics panel**: **built in full as of v1.0.0.** The RED (rate/errors/duration) metrics themselves landed in v0.7.0 — every package registers its own via `promauto` into a shared registry, gathered into `GET /metrics` alongside ingested/collected data (`internal/httpapi/selfmetrics.go`'s doc comment has the full list: HTTP, storage, scrape, remote-write, collect, alert, anomaly, backup). v1.0.0 added the dashboard-facing half: `GET /api/v1/selfmetrics` (JSON) plus a Self-metrics page (`web/static/js/selfmetrics.js`) that polls it every 5s and charts a short client-side rolling history, since these values were never written to `internal/storage` as their own time series. `/metrics` remains the text-format surface an external Prometheus/Grafana would scrape instead.
- API surface for the UI: a small `/api/v1/query_range` and `/api/v1/query` (naming deliberately close to Prometheus's HTTP API) so the frontend, and potentially external tools, can pull data without inventing a bespoke protocol.
- This is a **per-node local dashboard** (closer to netdata's local agent), not a multi-tenant/multi-host view — see [09 §9.2](09_design_tech_stack_and_roadmap.md) (resolved: strictly per-node).
