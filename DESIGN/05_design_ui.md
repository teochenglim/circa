# Circa — Design 05: Static HTML UI

- Build the frontend once (plain HTML/CSS/vanilla JS, or a small framework compiled to static assets) and embed it into the Go binary via `go:embed`, served from `/`. No Node.js runtime, no separate deploy artifact — this preserves the "single binary" property end to end.
- Charting library: **uPlot**. Benchmarks show it as by far the smallest and fastest canvas-based time-series charting library — at ~50 KB it's likely the smallest and fastest time series plotter that doesn't use WebGL/WASM, and when updating 3,600 points at 60fps it uses 10% CPU and 12.3MB RAM versus 40%/77MB for Chart.js and 70%/85MB for ECharts. For a single-binary tool aiming for a small footprint end-to-end, shipping a ~50KB dependency-free chart lib beats bundling Chart.js/ECharts/Plotly. One practical caveat from real-world use: uPlot's documentation is thin, mostly one markdown file plus reverse-engineering the TypeScript defs and demos, so budget extra time for chart wiring rather than assuming a quick integration.
- Dashboard sections to plan for: overview (system health at a glance), per-source chart groups (grouped by scrape target / line-protocol measurement / remote-write origin, not by a fixed collector taxonomy — see [04](04_design_collection_and_ingestion.md)), an alerts view, an anomaly/"what changed" view (see [06](06_design_alerting_and_anomaly_detection.md)), a **status/config page** (see [08](08_design_config_auth_ops.md)), and a lightweight **self-metrics panel** (see [08](08_design_config_auth_ops.md)).
- API surface for the UI: a small `/api/v1/query_range` and `/api/v1/query` (naming deliberately close to Prometheus's HTTP API) so the frontend, and potentially external tools, can pull data without inventing a bespoke protocol.
- This is a **per-node local dashboard** (closer to netdata's local agent), not a multi-tenant/multi-host view — see [09 §open questions](09_design_tech_stack_and_roadmap.md) for whether that's revisited later.
